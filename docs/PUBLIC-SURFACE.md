# 对外接口清单（判据的「公共接口」定义）

**这份文件是给门禁判据看的**：`change_preserves_public_api` 这条命题问的是「这次改动是否保持公共接口兼容」，
而「公共」必须有一个**本仓的**定义 —— 否则判据只能按最保守的口径办（任何导出名都算公共接口，
于是每次内部重构都被判成破坏性变更：实测两次 `0.07 / 0.11`，见 PR #85 / #86）。

> 判据吃到的文本：`docs/PUBLIC-SURFACE.md`（本文件）+ diff。口径发生争议时**以本文件为准**。

## 一、算公共接口（改动即可能不兼容）

| 面                       | 具体位置                                                                                                                              | 为什么算                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **会话协议**             | `vendor/pi-web-ui/server/protocol.ts`：`PROTOCOL_VERSION`、消息类型与字段                                                             | 前端与后端分属两个构建产物，靠版本号握手；字段语义变了必须 bump               |
| **HTTP 接口**            | `server/` 暴露的路由、`/api/*` 请求与响应形状、鉴权与 CORS 行为                                                                       | 外部客户端、脚本、看板都在调                                                  |
| **CLI 子命令与参数**     | `vendor/pi-web-ui/scripts/jev-gate.ts`（`check` / `ask` / `tune` / `review` …）、`scripts/jev-ask.ts`、`scripts/*.mjs` 的参数与退出码 | 人、CI、钩子按名字调用；退出码是契约                                          |
| **配置文件与安装布局**   | `<agentDir>/dev-con/*.json` 的字段、`extensions/<name>-<hash>.ts` 的发现规则、安装器产物路径                                          | 运维与升级脚本依赖（**已知破坏性先例**：删 `app.json` 见 `docs/JEV-HOOK.md`） |
| **被别的仓库消费的东西** | 发布出去的包、GitHub Action 的输入/输出、被别的仓 import 的模块                                                                       | 改它们会直接打断外部使用者                                                    |
| **持久化数据格式**       | `*.jsonl` 采样/统计/缓存的字段、日志中可被解析的行                                                                                    | 回放与复盘脚本按字段读                                                        |

## 二、不算公共接口（改动即视为兼容）

| 面                    | 具体位置                                                                                        | 为什么不算                                                                                                                    |
| --------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **扩展内部实现**      | `extensions/*/` 内部的函数与导出（如 `resolveApp` / `appFromHostEntry` / `classifyCliFailure`） | 扩展本体是**内容寻址复制件**（`<agentDir>/hooks/<name>-<hash>/`），消费者只有同仓单测；不存在跨版本消费者，所以故意不留弃用期 |
| **同仓单测**          | `tests/*` 的新增、改写、删除                                                                    | 测试是内部手段；判「测试是否断言具体行为」的是另一条命题                                                                      |
| **CI / 运维脚本内部** | `scripts/ci/*.mjs`、`scripts/maintenance/*.mjs`、`scripts/lifecycle/*.mjs` 的内部函数           | 只有本仓流程调用，且调用方随提交一起改                                                                                        |
| **文档与注释**        | `docs/*`、代码注释、breadcrumb                                                                  | 不影响任何调用方                                                                                                              |
| **私有模块间搬代码**  | 把函数从 A 私有模块挪到 B、重命名局部变量、调整内部层级                                         | 调用方不受影响                                                                                                                |

## 三、判断方法（判据请按这个顺序问自己）

1. **diff 里动的东西，有没有出现在第一节的表格里？** 没有 → 视为兼容（即使删了导出名、改了签名）。
2. 出现在第一节 → 看**外部怎样才能观察到**：名字、参数、返回值、类型、行为、退出码、字段名。
   只要有一项对外可见地变了，就是不兼容；纯新增（新导出、可选参数、放宽类型）是兼容。
3. **拿不准时**：如果这个符号只被同仓代码/单测引用，且它所在的本体是**按内容哈希整体复制**出去的
   （`extensions/*`、`<agentDir>/hooks/*`），按第二节办；否则按第一节办。

## 四、这份清单自己的变更

修改本文件 = 修改门禁口径。要求：

- PR 描述里写明「为什么某个东西从公共变成内部（或反过来）」；
- 同一 PR 里同步 `config/jev-settings.ci.json` 与本地 `dev-con/jev-settings.json` 的命题口径（如涉及）；
- 影响阈值标定时，用 `npm run jev -- tune` 重跑语料并记录结果（见 `docs/JEV-DECISION-GATE.md`）。
