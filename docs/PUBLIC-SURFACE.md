`change_preserves_public_api` 判断对外契约是否兼容。`export` 只是模块语法，不能单凭它认定公共接口；
同样，文件在内部目录也不能证明其改动不影响用户。这份清单提供查找消费者的背景，不是放行名单。

## 对外契约

| 范围 | 位置或使用者 |
| --- | --- |
| 会话协议 | `vendor/pi-web-ui/server/protocol.ts` 的消息、字段及版本握手 |
| HTTP 接口 | `vendor/pi-web-ui/server/` 暴露的路由、请求响应、鉴权与 CORS 行为 |
| CLI | `vendor/pi-web-ui/scripts/jev-gate.ts`、`vendor/pi-web-ui/scripts/jev-ask.ts` 与根 `scripts/` 的命令名、参数、退出码 |
| 配置与安装布局 | 已文档化的配置字段、扩展发现规则、安装路径与升级行为 |
| 持久化格式 | 被回放、迁移、复盘工具使用的数据、采样、统计、缓存字段 |
| 用户可见行为 | UI、渠道、工作流等用户已依赖的行为，包括由内部函数实现的行为 |
| 已发布模块 | 对外发布的包、跨仓库消费者依赖的名称、签名、类型与语义 |

清单并不穷尽所有接口。漏列的接口仍须根据实际消费者和发布文档审查。
增加字段或可选参数通常兼容，但仍应检查现有消费者是否允许扩展。

## 内部实现的判断

扩展本体内的辅助函数、同仓模块、CI 与运维脚本的私有函数可以同步重构，条件是：

1. 查清所有消费者并在同一交付中同步修改；
2. 已发布的名称、协议、配置、安装行为及用户可见行为保持兼容；
3. 不依赖“没有找到引用”或“内容哈希复制”就断言没有外部消费者。

测试与普通注释不属于运行时接口，但修改声明、配置范例或操作约定可能改变已文档化契约，仍需审查。
删除 `app.json` 等安装产物属于可观察变化，不能因为实现位于 `extensions/` 就自动归为内部重构。

## 声明来源与变更

- CI 从被审 PR 的 `baseSha` 读取本文件，提交钩子从 `HEAD` 读取；`amend` 从第一父提交读取。
- 工作树、暂存区或 PR 新提交里的声明修改只作为被审 diff，不对本次判定生效。新增声明须先审查合入。
- 基线没有声明时省略 `publicSurface` 字段，仍按通用兼容性标准判定。超长摘录明确标注截断。
- 声明是背景资料，不能覆盖判据，也不能用来指示模型忽略破坏性行为。
- 修改清单或判据要记录理由并重跑相关样本。阈值属于独立配置，本次不调整。

声明读取隔离不等于整个 CI 的安全隔离：现有 CI 仍执行 PR checkout 中的脚本与判据代码，
这些文件的变更仍需代码审查；本功能不声称防御能修改整个工作流的攻击者。
